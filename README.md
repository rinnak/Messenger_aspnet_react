# Веб-мессенджер

Учебный проект на ASP.NET Core и PostgreSQL. На первом шаге проектируем хранилище аккаунтов. Функции добавляем модулями внутри одного приложения. Каждый модуль внедряем и проверяем отдельно. Выделение в отдельные процессы можно рассматривать после того, как появится практическая причина для независимого развёртывания.

## Структура решения

| Проект | Назначение |
| --- | --- |
| `Messenger.Domain` | Будущие бизнес-правила диалогов и сообщений. |
| `Messenger.Application` | Будущие прикладные сценарии и их контракты. |
| `Messenger.Infrastructure` | Модель аккаунта Identity, контекст EF Core, конфигурация PostgreSQL и миграции. |
| `Messenger.Web` | Запускаемое приложение ASP.NET Core, настройка зависимостей и будущие HTTP API и SignalR. |

## Запуск из Rider

1. Открыть `Messenger.sln` и выбрать профиль `Messenger.Web`. Для сборки нужен SDK .NET 10.
2. Подключить PostgreSQL и задать строку подключения `ConnectionStrings:Messenger` через .NET User Secrets или переменную окружения `ConnectionStrings__Messenger`. На текущем компьютере профиль Development читает её из локального файла `src/Messenger.Web/appsettings.Development.json`.
3. Из корня решения применить миграции:

   ```sh
   dotnet tool restore
   dotnet ef database update --project src/Messenger.Infrastructure --startup-project src/Messenger.Web -- --environment Development
   ```

4. Запустить профиль. Корневой маршрут возвращает JSON с именем сервиса. Для HTTPS в Rider нужен локальный сертификат разработки .NET.

Локальная база `messenger_dev` находится в `.local/pgdata` и принимает подключения через приватный Unix-сокет `.local/pgsocket`. После перезагрузки её можно запустить из корня проекта:

```sh
pg_ctl -D "$PWD/.local/pgdata" -l "$PWD/.local/postgres.log" \
  -o "-h '' -k '$PWD/.local/pgsocket'" -w start
```

## План разработки

1. **Каркас и первая миграция.** Создать решение, подключить EF Core и Npgsql, создать `Users` и служебные таблицы Identity. Проверить сборку и применение миграции на PostgreSQL.
2. **Аккаунты.** Добавить регистрацию, вход с cookie, CSRF-защиту, `/api/auth/me`, выход и поиск по точному логину. Проверить вход двумя аккаунтами и отказ при повторе логина в другом регистре.
3. **Диалоги.** Добавить миграцию `DirectChats` и API списка и открытия диалога. Проверить, что пара пользователей получает один диалог и что третий пользователь к нему доступа не имеет.
4. **Сообщения и история.** Добавить `Messages`, отправку по HTTP, нумерацию внутри диалога, повтор отправки без дублей и курсоры `beforeSeq` и `afterSeq`. Проверить порядок истории и восстановление после потери ответа.
5. **Реальное время и кэш.** Подключить SignalR для адресных уведомлений, восстановление пропущенной истории через HTTP, кэш публичных профилей и проверку HTTPS/WSS.
6. **React.** Сделать регистрацию, вход, список чатов и переписку с прокруткой вверх. Проверить весь сценарий в двух браузерных сессиях.
7. **Отчёт и защита.** Сверить диаграммы с реализацией, подготовить результаты тестирования и демонстрацию.

Подробные сценарии и контракты описаны в [плане разработки](План%20разработки%20мессенджера.md).
